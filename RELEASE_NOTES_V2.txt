ОБЗОР РЕЛИЗА
============

Версия 2.0 представляет собой крупное обновление системы TaskBridge с добавлением
трех ключевых функций, запрошенных пользователями:

1. Множественные исполнители на одну задачу
2. Уведомления о новых комментариях к задачам
3. Фильтрация задач по создателю (для разделения задач разных руководителей)


НОВЫЕ ВОЗМОЖНОСТИ
=================

1. МНОЖЕСТВЕННЫЕ ИСПОЛНИТЕЛИ ЗАДАЧ
-----------------------------------

Описание:
  Теперь на одну задачу можно назначить несколько исполнителей одновременно.
  AI автоматически распознает всех упомянутых пользователей в сообщении.

Примеры использования:
  - "@alex @maria подготовьте презентацию к среде"
  - "Саша и Маша, срочно исправьте баг"
  - "@user1 @user2 @user3 проведите совещание"

Технические изменения:
  ✓ Создана таблица task_assignees (many-to-many связь Task <-> User)
  ✓ Добавлено поле assignees в модель Task
  ✓ Добавлено поле assignee_usernames (JSON) в модель PendingTask
  ✓ Обновлен AI промпт в bot/ai_extractor.py для извлечения массива username
  ✓ Обновлены обработчики в bot/handlers.py:
    - handle_group_message() - извлечение множественных исполнителей
    - handle_confirm_task() - назначение всех исполнителей
    - notify_assigned_user() - уведомление конкретного исполнителя
  ✓ Обновлен поиск активных задач через many-to-many join

Преимущества:
  + Командная работа над задачами
  + Все исполнители получают уведомления
  + Прозрачное распределение ответственности


2. УВЕДОМЛЕНИЯ О НОВЫХ КОММЕНТАРИЯХ
------------------------------------

Описание:
  При добавлении комментария к задаче все участники (создатель и исполнители)
  автоматически получают уведомление в Telegram.

Как работает:
  1. Пользователь добавляет комментарий через WebApp
  2. Система определяет всех участников задачи
  3. Каждому участнику (кроме автора комментария) отправляется уведомление
  4. Уведомление содержит кнопку "Открыть задачу" для быстрого перехода

Технические изменения:
  ✓ Создан новый модуль bot/notifications.py
  ✓ Добавлена функция notify_comment_added()
  ✓ Обновлен API endpoint POST /api/tasks/{task_id}/comments в webapp/app.py
  ✓ Асинхронная отправка уведомлений через asyncio.create_task()
  ✓ Обработка ошибок (не блокирует сохранение комментария)

Формат уведомления:
  "💬 Новый комментарий к задаче

  Задача: [название задачи]
  Автор: [имя автора]
  Комментарий: [текст комментария]"

Преимущества:
  + Мгновенная коммуникация по задачам
  + Никто не пропустит важное обновление
  + Увеличение вовлеченности команды


3. ФИЛЬТРАЦИЯ ЗАДАЧ ПО СОЗДАТЕЛЮ
---------------------------------

Описание:
  Руководители теперь видят только те задачи, которые они сами создали.
  Это предотвращает смешивание задач разных руководителей в одном списке.

Технические изменения:
  ✓ Добавлено поле created_by в модель Task
  ✓ Добавлена связь creator (User) в модель Task
  ✓ Обновлен API endpoint GET /api/tasks с параметром created_by
  ✓ При создании задачи автоматически сохраняется created_by_id
  ✓ API возвращает информацию о создателе в поле creator

Использование в API:
  GET /api/tasks?created_by=5

  Вернет только задачи, созданные пользователем с ID=5

Преимущества:
  + Разделение задач между руководителями
  + Чистота данных в интерфейсе
  + Упрощенный контроль своих задач


ОБНОВЛЕНИЯ API
==============

Изменения в GET /api/tasks:
----------------------------
БЫЛО:
  {
    "assignee": { ... }  // один исполнитель
  }

СТАЛО:
  {
    "assignees": [ ... ],  // массив исполнителей
    "creator": { ... }     // создатель задачи
  }

Новые параметры фильтрации:
  - created_by: int - фильтр по создателю задачи
  - assigned_to: int - фильтр по исполнителю (работает с many-to-many)

Изменения в GET /api/tasks/{task_id}:
--------------------------------------
  Возвращает те же поля: assignees (массив) и creator


Изменения в POST /api/tasks/{task_id}/comments:
------------------------------------------------
  После создания комментария автоматически отправляются уведомления
  всем участникам задачи (асинхронно).


ИЗМЕНЕНИЯ В БАЗЕ ДАННЫХ
========================

Новые таблицы:
--------------
1. task_assignees
   - task_id INTEGER (FK -> tasks.id) ON DELETE CASCADE
   - user_id INTEGER (FK -> users.id) ON DELETE CASCADE
   - assigned_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
   - PRIMARY KEY (task_id, user_id)

Новые поля:
-----------
1. tasks.created_by INTEGER (FK -> users.id)
   - Индекс: idx_tasks_created_by

2. pending_tasks.assignee_usernames TEXT (JSON массив)
   - Хранит список username исполнителей: ["user1", "user2"]

Индексы:
--------
  - idx_tasks_created_by ON tasks(created_by)

Устаревшие поля (сохранены для обратной совместимости):
--------------------------------------------------------
  - tasks.assigned_to - помечено как DEPRECATED
  - pending_tasks.assignee_username - используется как fallback


МИГРАЦИЯ БАЗЫ ДАННЫХ
=====================

Файл миграции: db/migrate_v2.py

Что делает миграция:
--------------------
1. Создает таблицу task_assignees (если не существует)
2. Добавляет поле created_by в таблицу tasks
3. Добавляет поле assignee_usernames в таблицу pending_tasks
4. Мигрирует данные из assigned_to в task_assignees
5. Создает необходимые индексы

Как запустить:
--------------
cd C:\Users\Владислав\Desktop\TaskBridge_prototype
python -m db.migrate_v2

Важно:
------
  ⚠ Миграция должна быть выполнена ПЕРЕД запуском обновленного кода
  ⚠ Миграция безопасна и не удаляет существующие данные
  ✓ Миграция идемпотентна (можно запускать несколько раз)

=====================

1. WebApp UI не обновлен:
   - index.html еще показывает только одного исполнителя
