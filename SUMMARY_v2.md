# TaskBridge v2.0 - Сводка изменений

## 🎯 Выполненные задачи

### 1. ✅ Множественные исполнители
**Статус:** Реализовано и протестировано

**Backend изменения:**
- Создана таблица `task_assignees` для связи many-to-many
- Добавлено поле `created_by` в таблицу `tasks`
- Обновлены модели SQLAlchemy с relationships
- Модифицирован AI-экстрактор для парсинга массива username'ов
- Обновлены bot handlers для работы с множественными исполнителями
- Создан скрипт миграции `db/migrate_v2.py`

**Файлы:**
- `db/models.py` - новая таблица и отношения
- `bot/ai_extractor.py` - парсинг массива исполнителей
- `bot/handlers.py` - уведомления всем исполнителям
- `webapp/app.py` - API возвращает массив assignees

### 2. ✅ Уведомления о комментариях
**Статус:** Реализовано

**Реализация:**
- Создан модуль `bot/notifications.py` с функцией `notify_comment_added()`
- При добавлении комментария уведомления получают:
  - Создатель задачи (если не автор комментария)
  - Все исполнители (кроме автора комментария)
- Уведомления отправляются асинхронно через `asyncio.create_task()`

**Файлы:**
- `bot/notifications.py` - новый модуль для уведомлений
- `webapp/app.py` - POST /api/tasks/{id}/comments с уведомлениями

### 3. ✅ Фильтрация по создателю
**Статус:** Реализовано

**Реализация:**
- Добавлен параметр `created_by` в GET /api/tasks
- Manager Mode фильтрует задачи по текущему userId
- В ответе API возвращается информация о создателе

**Файлы:**
- `webapp/app.py` - фильтр created_by
- `webapp/src/components/ManagerMode.jsx` - использование фильтра

### 4. ✅ Улучшенный парсинг времени
**Статус:** Реализовано

**Новые возможности:**
- Части дня: "утром" (09:00), "в обед" (13:00), "вечером" (18:00), "ночью" (00:00)
- Дни недели: "в понедельник", "к пятнице" и т.д.
- Относительные даты: "через 2 дня", "через неделю", "через месяц"
- Конкретное время: "к 10:00", "до 15:30", "в 18 вечера"
- Умная логика: если время прошло сегодня, переносит на завтра

**Файлы:**
- `bot/ai_extractor.py` - расширенные правила парсинга времени

### 5. ✅ React WebApp с управлением исполнителями
**Статус:** Реализовано и собрано

**Компоненты:**
- `TaskList.jsx` - список задач с карточками
- `TaskDetail.jsx` - детальный просмотр с управлением исполнителями
  - Модальное окно для добавления исполнителей
  - Кнопки удаления исполнителей (только для менеджеров)
  - Комментарии
  - Файлы
  - Изменение статусов

**API для управления исполнителями:**
- POST `/api/tasks/{task_id}/assignees` - добавить исполнителя
- DELETE `/api/tasks/{task_id}/assignees/{user_id}` - удалить исполнителя
- При добавлении исполнителю приходит уведомление в Telegram

**Дизайн:**

- Цветовая индикация статусов и приоритетов
- Адаптивная верстка
- Модальные окна
- Интеграция с Telegram WebApp темами

**Файлы:**
- `webapp/src/components/*.jsx` - все React компоненты
- `webapp/src/styles/main.css` - основные стили
- `webapp/src/services/api.js` - API клиент
- `webapp/dist/` - production сборка

## 🚀 Как запустить

### Простой способ (Windows)
```bash
start_all.bat
```

### Ручной запуск
```bash
# 1. Активировать venv
source venv/bin/activate  # Linux/Mac
venv\Scripts\activate     # Windows

# 2. Запустить бота
python bot/main.py

# 3. Запустить веб-приложение (в другом терминале)
uvicorn webapp.app:app --host 0.0.0.0 --port 8000
```

### Пересборка React приложения
```bash
# Windows
rebuild_webapp.bat

# Linux/Mac
cd webapp
npm install
npm run build
```

## 🐛 Известные ограничения

1. Уведомления работают только для пользователей, которые:
   - Авторизованы в боте
   - Имеют telegram_id != -1

2. React приложение требует пересборки после изменений:
   - Используйте `npm run dev` для разработки с hot-reload
   - Или `rebuild_webapp.bat` для production сборки

3. Модальное окно выбора исполнителей показывает всех пользователей:
   - В будущем можно добавить поиск
   - Можно добавить группировку по ролям
